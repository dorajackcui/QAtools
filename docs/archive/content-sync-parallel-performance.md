# 内容同步并行实测（2026-09-11）

本记录是在[首次评估](content-sync-performance.md)后的实现验证，不改变空白、公式缓存、冲突优先级或输出规则。
当前运行约定统一见[工具 README](../../tools/content_sync/README.md#性能评估)。

## 实现选择

使用标准库 ThreadPoolExecutor，增加一个工具包内的有界调度模块，不新增依赖、进程入口或 GUI 设置。
正向独立处理小表并返回各自 FileResult；反向只并行读取，再按原排序合并并保存一次 Master。
工作线程不修改共享计数，不直接调用日志和进度回调。

选择正向默认 2 个任务：多小表、多列场景有收益，其他场景相近。反向默认仍为 1：
大表解析与最终 Master 保存成本无法通过并行读取小表消除，所测收益不足以支持默认开启。
两个方向保留显式任务数，便于用实际工作簿比较。Excel COM 以及符号链接目标仍走串行路径。

## 测量方法

Windows 10 x64（19045）、Python 3.11.6、openpyxl 3.1.5，本机临时目录。
每个样本独立 Python 进程，先生成文件再计时，不包含样本生成；所有输出均在临时目录中。
沿用首次评估的工作簿生成器和 GUI LogBuffer，含真实日志格式化与入队，不含弹窗绘制。
每种场景分别运行串行和 2 线程，各 3 次；第二轮颠倒两种模式的运行顺序。

比较并行时关闭阶段插桩，仅测整个业务调用的墙钟时间。串行阶段计时器使用共享嵌套栈，
不可用于多线程；脚本会拒绝未指定 `--wall-only` 的并行阶段测量。
结果为 3 轮耗时中位数、3 轮进程峰值 RSS 的最大值。RSS 包含导入及样本生成。

复现全套对比（两条命令分别运行，请勿同时执行以免相互干扰）：

```powershell
python scripts/benchmark_content_sync.py --workers 1 --wall-only --repeat 3 > build/sync-serial.jsonl
python scripts/benchmark_content_sync.py --workers 2 --wall-only --repeat 3 > build/sync-parallel.jsonl
```

单场景适合交替重复比较：

```powershell
python scripts/benchmark_content_sync.py --case many --direction forward --workers 1 --wall-only
python scripts/benchmark_content_sync.py --case many --direction forward --workers 2 --wall-only
```

`--case` 每次执行一轮；不传 `--case` 时才使用 `--repeat`。原阶段分析仍使用 `--workers 1`，不加 `--wall-only`。

## 结果

| 场景（总行数 / 小表数 / 内容列数） | 方向 | 串行（秒） | 2 线程（秒） | 耗时减少 | RSS 串行 / 并行（MiB） |
|---|---|---:|---:|---:|---:|
| 多小表：20,000 / 200 / 1 | 正向 | 6.383 | 4.224 | 33.8% | 67.9 / 69.7 |
| 大总表：20,000 / 20 / 1 | 正向 | 2.608 | 2.622 | -0.5% | 73.1 / 74.8 |
| 多列：10,000 / 20 / 12 | 正向 | 6.626 | 5.664 | 14.5% | 86.1 / 89.1 |
| 多小表：20,000 / 200 / 1 | 反向 | 3.103 | 3.189 | -2.8% | 113.4 / 113.2 |
| 大总表：20,000 / 20 / 1 | 反向 | 2.706 | 2.669 | 1.4% | 113.1 / 113.9 |
| 每 10 行含缓存公式：10,000 / 20 / 1 | 正向 | 1.898 | 1.755 | 7.5% | 101.1 / 100.2 |
| 每 10 行含缓存公式：10,000 / 20 / 1 | 反向 | 1.861 | 1.773 | 4.7% | 83.5 / 83.3 |

所有 42 次调用均断言零失败，更新数等于总行数乘更新列数。数据是合成样本，不能保证真实文件按同一比例提速；
小幅差异应视为波动。四线程允许显式使用，但本轮没有测量，不作为默认推荐。
COM 执行保持原串行路径，本轮没有重新测量原生 Excel 性能。

## 正确性验证

- 对照串行/并行的完整结果对象、逐条日志、进度以及 Excel ZIP 内容（只忽略保存时间元数据）。
- 人为让后文件先读完，验证重复身份、空白策略、仅填空及冲突来源顺序不变。
- 注入单文件保存失败、损坏文件、缺少公式缓存，验证不计未落盘更新、不合并失败文件的部分内容。
- 显式管理来源二进制流，避免中断的只读解析器在失败返回后继续占用 Windows 文件。
- 验证任务提交有界、结束后线程退出、回调与 COM 仍在协调线程。
- GUI 集成测试同时阻塞两个文件任务，由 GUI 定时器打开日志并释放任务，验证界面事件循环继续响应。

自动化入口为 `tests/test_content_sync_parallel.py`、`test_content_sync_gui.py` 及既有内容同步、工具和 CLI 回归。
本轮全量运行 532 项测试，无失败，13 项因环境或显式集成开关跳过；compileall、diff 检查和文档检查通过。
