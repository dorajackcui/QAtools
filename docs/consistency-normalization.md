# 一致性检查的文本归一化

“同 Source 不同 Target”“同 Target 不同 Source”和“子串译文一致性”共用本规则。
Source 与 Target 都先生成用于比较的文本；原单元格、报告原文和修订回填的原文核对
不做改写。其他检查不受本规则影响。

## 比较文本

1. 去除文本首尾空白，包括空格、制表符、换行及 NBSP。
2. 去除包裹整个文本的成对引号或括号。
3. 重复以上步骤，支持多层包裹及包裹内侧的空白。

支持的包裹符号：

- 引号：`"…"`、`'…'`、`“…”`、`‘…’`、`「…」`、`『…』`、`«…»`、`‹…›`、`＂…＂`、`＇…＇`。
- 括号与书名号：`【…】`、`[…]`、`［…］`、`(…)`、`（…）`、`《…》`、`〈…〉`、`〔…〕`、`〖…〗`。

例如 `阿童木`、`“阿童木”`、`【阿童木】`、` 【 ‘阿童木’ 】 ` 使用相同的比较文本。
`“Astro Boy”` 与 `Astro Boy` 也视为相同。

只移除包裹整个文本的一对符号，不删除正文内部标记；`【阿童木】登场`、
`“阿童木”和“悟空”`、`[A] 与 [B]` 保持原样。不成对符号、内部空格、内部换行、
其他标点、Tag、花括号占位符均保留；`{name}`、`<name>` 不归一成 `name`。
不转换全半角正文、Unicode 组合形式或大小写。子串检查已有的 Target 忽略大小写规则
仍由[子串检查规则](../tools/substring_consistency_checker/README.md#规则)定义。

## 检查与报告

- 双向一致性检查使用归一化后的文本分组，并统计另一列归一化后的版本数。
  仅包裹符号不同不会增加版本数；真实的文本差异仍会报告。
- 归一化后为空按空文本处理，各检查对空值的处理见对应工具 README。
- 子串检查使用归一化后的 Source 判断重复、参考资格和包含关系；使用归一化后的
  Target 判断参考译文是否冲突及是否匹配。归一化后相同的 Source 不作为彼此的子串。
- 报告保留每行原文；双向一致性组与组内译文版本的展示顺序也使用相同比较文本。
- 子串参考组的 Source / Target 展示首个参考行的原文，其他参考行可能有不同包裹形式，
  但归一化后等价。报告格式见[子串检查说明](../tools/substring_consistency_checker/README.md#报告与性能)。
- 回填仍按原行号及原始 Source 精确核对，不因归一化放宽冲突校验。

实现位于 [consistency_text.py](../tools/consistency_text.py)，测试位于
`tests/test_consistency_text.py`，三个检查及统一报告另有集成测试。
