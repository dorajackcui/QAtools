PhraseLoom 怎么把重复文案变少，还不弄坏格式？

你可以把主流程理解成两个小帮手：第一个先把不能翻坏的格式锁起来， 第二个把大量相似句子合并成少量翻译任务。译员翻完后，系统再把格式还原并写回 Excel。

看 Entity Engine
先锁格式

标签、换行、图片、占位符先变成临时编号，避免翻译时被误删或改坏。

再合并重复

只差数字或颜色的句子合并成一条模板，译员不用重复翻很多遍。

最后写回

系统把每行自己的数字填回去，再把临时编号还原成原始格式。

先看一个完整例子

Excel 里原本长这样

<color=#ff0>VIP10 Pack</> <color=#ff0>VIP20 Pack</>
→

译员只需要处理模板

{1>VIP{num1} Pack<2} 翻成：{1>Pack VIP{num1}<2}
→

系统自动生成每一行

<color=#ff0>Pack VIP10</> <color=#ff0>Pack VIP20</>
1
用户看到的开始

把源 Excel 交给 PhraseLoom

文件里有 source 列，也可能已经有一部分 target 列。PhraseLoom 先逐行读取原文， 记住每一行来自 Excel 的哪一行，后面才能准确写回去。

原文 <color=#ff0>VIP10 Pack</> Buy 200 coins
→
PhraseLoom 记住 第 2 行是什么文案 第 3 行是什么文案
2
Tag Engine：保护格式

先给不能翻坏的东西贴临时号码牌

颜色标签、图片标签、换行、原始占位符这些内容通常不应该被翻译。 所以系统先把它们换成短编号。译员看到编号，但不用碰原始标签。

原始格式 <color=#ff0>VIP10</> Hit deals {0} damage
→
临时号码牌 {1>VIP10<2} Hit deals {1} damage
3
Template Engine：减少重复

再把相似句子合并成一条模板

很多文案只是数字不同，例如 VIP10、VIP20、VIP30。系统会把变化的数字抽出来， 变成一个变量。这样译员只翻一个句式，系统负责替换每一行自己的数字。

很多相似句 VIP10 Paid Pack VIP20 Paid Pack VIP30 Paid Pack
→
一条模板 VIP{num1} Paid Pack {num1} 代表每行自己的数字
4
译员真正要处理的文件

生成 translator todo，译员只填 target_unit

PhraseLoom 会输出一个给译员用的 workbook。译员不需要管每一行 Excel， 只需要翻译去重后的 unit。能从 TM 或 existing target 推断出来的内容，会先预填好。

译员看到 source_unit: VIP{num1} Paid Pack target_unit: ______
→
译员填写 target_unit: Pack VIP{num1} 变量名保留，不要翻译
5
系统自动回填

把模板套回每一行，再恢复原始格式

回填时系统先把每行自己的数字填进译文模板，再检查临时编号有没有丢， 最后把编号换回原始标签和占位符。

中间结果 {1>Pack VIP10<2} {1>Pack VIP20<2}
→
写回 Excel <color=#ff0>Pack VIP10</> <color=#ff0>Pack VIP20</>
6
人工检查点

有风险的地方会写 warning，不会偷偷吞掉

如果目标译文少了一个临时编号、多了一个不存在的编号、模板缺变量，或者某些句子涉及价格和单复数， PhraseLoom 会在报告里提示 PM 或译员检查。

可能的风险 target_unit 少了 {num1} 译文少了 {1> 或 <2}
→
用户动作 看 warning 确认是否需要手动修正

Tag Engine 是保险箱

它只负责保护和恢复格式，不负责判断译文好不好。

Template Engine 是复用器

它把重复句式变少，不代替译员做语言判断。

translator todo 是工作台

译员主要填这里的 target_unit；最终写回由系统完成。
