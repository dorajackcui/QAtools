# 内容同步：Master ↔ 小表

按 **Key + 原文** 将 Master 总表内容写入目录中的小表，支持单列或连续多列。
反向入口把小表译文回填到 Master。业务层使用 openpyxl，无需 pandas；
仅正向的可选兼容性重存需要本机 Microsoft Excel。

两个方向位于统一 GUI 的同一页面，以两个 Tab 切换；CLI 为 `qatools content-sync`，参数见[CLI 手册](../../docs/cli-usage.md#内容同步)。
切换 Tab 时分别保留各自的配置、结果和日志，后台任务继续运行。

## 操作

启动 QAtools，在侧栏【常用流程】中打开【内容同步】，选择【Master → 小表】Tab：

1. 选择 Master 总表和小表目录。小表目录会递归扫描。
2. 【新输出目录（可选）】默认留空，直接更新小表目录中的原文件。
   如需副本，填写尚不存在的新目录，或点击【选择位置】指定另存位置；清空此项即可恢复原位更新。
3. 分别填写 Master、小表的 Key、原文、内容开始列，使用 `A`、`B`、`AA` 等列字母。
   默认 Master 为 B/C/D，小表为 A/B/C；本页列配置为手动指定，不自动推断。
4. 选择工作表并设置表头行数。默认活动表、1 行表头；小表工作表留空表示逐文件使用活动表。
   没有表头可设为 0。
5. 设置连续更新列数和写入选项，点击【同步到小表】。底部【查看日志】可实时查看详情，完成后显示结果摘要。

### 选择阶段检查

两个 Tab 在点击【选择文件】或【选择目录】并确认路径后，后台执行以下检查：

- Master：Windows 上通过短暂的只读独占打开检查当前占用，立即释放句柄，不改动文件。
  发现占用、文件只读、访问状态无法确认或 Excel 临时锁文件时弹窗提醒；临时锁文件也可能是残留，不能认定为正在编辑。
  同时读取工作表列表；读取失败也会显示原因。无异常时不弹出 Master 提示。
- 小表目录：沿用对应同步方向的递归扫描与排除规则，弹窗显示可处理 `.xlsx/.xlsm` 文件总数、
  不支持格式数，随机抽检最多 20 个候选文件（不足 20 个则全部检查），列出只读和无法检查的样本。
  只检查操作系统文件只读属性，不打开 Excel，也不检测工作簿写保护、权限 ACL 或小表占用。
- 弹窗明确标注抽检数量，未抽到只读文件不代表整个目录可写。正向原位更新提醒只读风险，
  另存提示不覆盖原小表；反向提示只读小表仍可作为来源读取。
- 扫描期间表单与运行按钮暂时禁用，界面事件循环、日志和其他 Tab 仍可响应。
  检查结束恢复操作；选择检查失败不清除上一次运行结果与日志。

这些提醒是选择当时的快照，不修改文件属性、不自动关闭 Excel，也不改变运行时规则。
先选目录再更换 Master 或输出位置时，目录统计可能变化，可重新选择目录复查。
运行时仍重新扫描并保留实际读取、保存失败处理；只读来源不会因预检查被禁止使用。

## 匹配与搬运规则

本节的 Master 来源、小表目标指正向同步；反向差异见下方【小表 → Master】。

- Key 和原文分别转成字符串并去首尾空白，再作为二元组精确匹配；大小写不同不匹配。
- 任一身份字段为空则跳过；不按 Key 单独匹配，也不追加新行。
- 目标重复身份的所有匹配行都会处理；Master 重复身份采用后行的完整内容组。
  即使后行内容为空，也先采用后行，再应用空白写入策略；日志记录前行、采用行及内容差异。
- 单列和连续多列使用同一套规则；源和目标从各自内容开始列按顺序对应。
- Key、原文和内容列范围不能重叠。缺少 Key/原文列时报错；Master 内容范围缺少的单元格视为空内容。

### 空白与正文保留

| 输入 | 搬运内容 |
| --- | --- |
| 真正空单元格 / Python `None` | 空内容，绝不写成文字 `None`、`nan` 或其他转义占位符 |
| 用户输入的文字 `None`、`nan`、`NA`、`NULL` | 原样保留，不解释为缺失值 |
| 0 / False / 日期等非字符串值 | 用 `str(value)` 转为正文文本，0 和 False 都不是空白 |
| 文本 `00123` | 保留前导零；不根据 Excel 显示格式重新渲染数值 |
| 首尾空格、换行、Tag、标点 | 保留完整正文，不套用身份字段的裁剪规则 |
| 纯空白字符 | 保留原字符，但在写入策略中算作空白来源 |

同步内容写为文本，包括原本就是文本的 `=…` 或 `#N/A`，不会被新解释成公式或 Excel 错误。
覆盖模式下，目标即使是相同字面的公式或错误，也会转为文本；“仅填空”仍保留这些已有内容。

### 两个独立的写入选项

- **仅填空**：默认关闭。开启后，只更新小表中的空单元格或纯空白文本；已有内容保留。
- **允许空白写入**：默认关闭。关闭时，Master 空内容、纯空白来源都跳过，不修改目标；
  开启后，空内容可清空目标，纯空白字符则原样写入。仍须满足“仅填空”的目标限制。
- 连续多列逐单元格判断以上选项；目标原值已与拟写入文本相同时计为无变化。

### 公式

- Master 配置列中的公式读取最近一次保存在文件里的缓存值，转为文本搬运；本工具不计算公式。
- 公式没有可用缓存时，整次任务在创建输出前停止。请先在 Excel 中计算并保存，或转换为值；
  不能把缺失缓存当成真实空白去清空小表。已有缓存也可能过期，需确保 Master 已计算保存。
- 小表 Key/原文需要直接值；其中含公式时，该文件失败，不保存修改。
- 小表内容列的公式在“仅填空”模式下算作已有内容；覆盖模式下允许被新内容替换。
  未被更新的其他公式保留，工具不重新计算。

## 输出和错误处理

- 支持 `.xlsx/.xlsm`；修改工作簿时保留工作表结构、样式和 VBA 内容。特殊对象的兼容范围
  受 openpyxl 支持范围限制。可选 Excel 重存不能恢复读取时已丢失的特殊对象。
- 输出留空时直接更新原小表，Master 来源始终不修改。填写输出时另存到**尚不存在的新目录**，
  保留小表相对路径；填写已存在的目录会报错。GUI 更换输入目录不会自动填写或覆盖输出选项。
- 无变化时，原位模式不重写文件，另存模式逐字节复制。发生变化时先保存临时文件，
  成功后才替换原文件或放到另存路径；保存失败时原文件保留。
- 默认忽略锁文件 `~$*`、Master 本身、`.qatools-backups` 备份树、另存输出树及本次应用会话已生成的结果子目录。
  `.xls/.xlsb` 记为跳过；其他格式不参与。没有支持的小表时不生成输出。
- 一个小表读取、配置或保存失败时，继续处理其他小表。失败文件不输出，实际写入数不计入失败文件。
  GUI 会明确提示部分失败；已生成的成功文件可用。
- 不额外生成 report 文件。运行日志按文件显示单行摘要，包含状态、匹配行数和实际更新格数，
  按需补充策略跳过数、身份为空行数、未匹配行号（最多 12 个）和失败原因。
  输出位置每次任务显示一次，重复身份冲突另列；完整计数仍保留在内存结果中。
  `master_row_count` 表示有效身份去重后的数量；不等于扫描过的 Excel 物理行数。
- 日志容量、关闭/重开行为与历史输出识别范围见[运行日志](../../docs/tool-logs.md)。

### 可选兼容性重存

正向页面可勾选【同步后用 Excel 兼容性重存】，默认关闭。启用时先验证 Excel 能否启动，
再开始写入；只重存本次实际更新的小表。原位模式重存更新后的原文件，另存模式重存副本。
运行环境与重存行为见[兼容性重存](../excel_compatibility/README.md)。

某文件重存失败时保留已同步内容，在日志中写明原因，并计为失败文件；
`updated_cells` 仍包含已完成的同步写入。Excel 退出失败单独报告警告，不隐藏结果。

## 小表 → Master

在【内容同步】页面切换到【小表 → Master】Tab，选择总表、小表目录及列配置，点击【回填 Master】。
此方向只回填一列，没有连续多列选项。输出默认留空，直接回填原 Master；
填写新输出目录时，生成与原 Master 同名的副本。小表来源始终不修改。

- 以同一套 Key + 原文匹配及正文转换规则搬运小表内容，Master 不新增行；所有重复目标行都会更新。
- 小表按完整路径不区分大小写排序（相同排序键再按原路径排序），后文件、同文件后行优先。
  默认在决定优先级之前跳过空白来源，因此后面的空白不会遮住前面的非空译文。
  开启【允许空白写入】后，空白也参与覆盖。
- 汇总后一次写入 Master；【仅填空】针对原 Master 的内容判断，不让读取顺序改变填空结果。
- 小表配置列公式使用缓存值；任一有效身份行缺少公式缓存，整个来源文件失败，其前面已读内容也不参与汇总。
  其他文件继续。Master Key/原文必须是直接值；其中公式会使 Master 回填失败。
- 至少一个小表成功读取后才保存 Master；无变化时原位模式不重写，另存模式复制原文件。
  所有小表读取失败则不保存。Master 保存失败时原文件保留，不留下半成品；成功读取的小表数不代表 Master 保存成功。
- 运行日志记录每个来源文件、Master 保存结果、同文件/跨文件覆盖来源、
  未在 Master 中找到的候选身份、实际更新数及输出位置。摘要的成功项包括已读小表和已保存 Master。
- 目录、格式、表头、样式保留、原文件保护和空白正文规则与正向相同。反向不自动执行 COM 重存，
  如需可在生成后使用独立的兼容性重存入口。

本工具针对独立总表/小表。PhraseLoom 的 Strings 隐藏映射与 Batch 的 manifest 复原流程
仍分别使用各自入口。

## 性能评估

正向默认同时处理 2 个独立小表，共享只读 Master 索引；只有一个小表时直接串行。
反向支持并行读取，但本机基准收益不稳定，因此默认仍串行；汇总与 Master 保存始终由一个后台任务执行。
两个方向的 Python 入口均接受 `workers=1..4`，CLI 对应参数见[手册](../../docs/cli-usage.md#内容同步)。
GUI 沿用默认值，不增加设置项。

- 最多保持指定数量的小表任务在途，不一次提交整个目录；每个文件独立打开、关闭工作簿。
- 结果按原排序依次汇总，包括失败结果。反向仍然是后文件、同文件后行优先；空白与公式规则不变。
- 计数、日志及进度回调只在协调任务中更新；文件保存成功后才计实际写入。
  日志仍每文件一行，前面的文件较慢时，后面的已完成结果会等待它再显示。
- 启用 Excel 兼容性重存，或正向输入包含符号链接文件时，自动串行，保持原处理顺序与 COM 线程归属。
- GUI 的文件处理及等待都在后台，运行日志继续通过有界队列定时刷新。

并行收益依赖文件数量、内容与磁盘；可以用 `workers=1` 对照测量。
本机三轮对比、复现方式与限制见[并行性能记录](../../docs/archive/content-sync-parallel-performance.md)；
此前阶段耗时见[首次评估](../../docs/archive/content-sync-performance.md)。
