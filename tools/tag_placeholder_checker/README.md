# Excel Tag / Placeholder 检查工具

统一 CLI：`qatools tag-check --help`。

用于读取一份双语 Excel，逐行检查 `source` / `target` 中的常规 Tag 或 memoQ Marker 是否一致，并输出新的检查结果 Excel。

处理完成后会生成新的检查结果 Excel，并新增两个工作表：

- `标签占位问题`：列出 tag / placeholder 不一致的问题
- `检查汇总`：列出统计信息

这两个名称是工具保留的结果表名；输入工作簿中如果已有同名工作表，结果文件中会按预期重建它们。

## 规则

- 输入为一份双语 Excel：`source` / `target`
- 默认使用“常规 Tag”模式，检查四类片段：
  - `<...>`：按 tag 处理，包括空 tag `<>` 和仅含空白的 tag `< >`
  - `[color=...]`、`[/color]`：按方括号 color tag 处理
  - `{...}`、`{{...}}`：按 placeholder 处理，包括 `{1}`、空 placeholder `{}`
  - `\n`：按独立 mark 处理
- “memoQ Marker”模式只检查 `{n}`、`{n>`、`<n}`，其中 `n` 为数字
- 默认逐行比较 source / target 中的片段及出现次数
- `<...>` 会识别引号属性中的 `>`；`<>` 和 `< >` 会作为 tag，但尖括号内含非空白内容且首尾带空白的普通比较表达式（如 `value < 10 and count > 0`）不作为 tag
- 属性引号的结束位置按文本建立一次索引，避免残缺 Tag 中多次遇到 `<` 时重复扫描整段后缀；识别和转义规则不变。
- 常规模式会识别 `{1}`，也会把整段 `{2>Glace du Néant<3}` 作为一个花括号 placeholder，但不会单独捕获 `{2>`、`<3}`
- memoQ 模式会把 `{1}{2>Glace du Néant<3}` 识别为 `{1}`、`{2>`、`<3}`
- `memoq` 是独立检查类型；显式同时选择 `brace` 和 `memoq` 时，纯数字 `{n}` 只归入 `memoq`，避免重复报告；旧的 `numeric` 参数仍兼容，但不推荐继续使用
- 会检查：
  - target 缺少 source 中已有的片段
  - target 多出 source 中没有的片段
  - 同一片段数量不一致
  - 成对尖括号 tag 的闭合或父子层级不一致；默认允许并列 tag 片段因翻译语序调整而换序
- 当前按片段原样精确比较，例如 `<b>` 与 `</b>`、`{name}` 与 `{Name}` 会被视为不同内容
- 可选“检查 Tag 顺序”，默认关闭；开启后，所选类型经过过滤后提取出的完整片段序列必须在类型、原始内容、数量和出现顺序上逐一对应，包括不同类型之间的相对顺序。例如 `<br/>{name}` 与 `{name}<br/>` 会报错；正文翻译及片段的字符位置不参与比较。
- 顺序选项适用于常规 Tag 和 memoQ Marker。已有缺失、多出、内容或结构问题时沿用对应问题描述；只有片段及数量一致、结构检查通过但顺序不同时，报告 `Tag顺序不一致`，并列出 source / target 的片段顺序。

## 使用与维护

统一 GUI：一键质量检查 → Tag / Placeholder；常规与 memoQ 模式互斥。
“检查 Tag 顺序”可在同一设置窗口勾选，并随“记住选项”保存。
尖括号过滤 JSON 默认不启用；启用后的过滤方式仍由处理器配置决定。
旧脚本 `check_tags_and_placeholders_gui.py` 转接到 Qt QA 页并仅预选 Tag 检查，输出统一 QA 报告。

CLI 参数、组合 token 与过滤配置示例见 [CLI 手册](../../docs/cli-usage.md#参数速查)。
默认输出 `tag_check_<原文件名>`；不要将独立检查器的两个结果表等同于统一 QA 报告。

## 输出说明

`标签占位问题` 工作表包含以下列：

- `行号`
- `source原文`
- `target原文`
- `问题描述`
- `问题类型`

同一原始行命中多个问题类型时只输出一行，各问题用 `；` 合并。

`检查汇总` 工作表包含以下统计项：

- 检查工作表
- source / target 列
- 开始行
- 检查类型
- 总行数
- 命中检查类型行数
- 含尖括号 tag 行数
- 含方括号 color tag 行数
- 含花括号 placeholder 行数
- 含 `\n` mark 行数
- 含 memoQ marker 行数
- 问题行数
- 问题条数

问题描述直接列出差异，例如 `缺少：{name}；多出：{user}`，差异片段保留次数
（如 `缺少：{name} x2`）。结构问题显示 `嵌套或闭合结构不同`；顺序问题显示
`原文：{a} → {b}；译文：{b} → {a}`。原有“问题类型”列和统计保持不变。
